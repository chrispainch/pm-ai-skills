# Wardley Strategy

Use Wardley Maps as a strategy method, not as decoration. Anchor on user needs, map the landscape, identify climatic forces and inertia, then propose context-specific plays.

Treat the visual map as a derived view for humans. Treat the primary working artifact as a structured map that can be inspected, updated, diffed, and rendered.

## Workflow

1. Define scope, users, and their needs.
2. Build a structured map of the components and relationships needed to meet those needs.
3. Position components by evolution: `genesis`, `custom built`, `product`, or `commodity / utility`.
4. Surface assumptions, missing components, duplication, and bias.
5. Apply climatic patterns and doctrine.
6. Propose plays, risks, and open uncertainties.
7. Render the structured map into tables, prose, or a visual map only when helpful.

## Output

For persistent files, follow the shared output policy in the repository's `AGENTS.md`. Use a human-readable review only when it adds value.
