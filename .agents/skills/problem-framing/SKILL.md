# Problem Framing

Define the problem before defining a solution. Produce a decision-quality brief, not a feature request or a generic research summary.

## Workflow

1. Define the decision, target segment, triggering context, and alternatives or workarounds.
2. Separate direct evidence, internal signals, market inference, and assumptions.
3. State the user need, gap, desired user outcome, and plausible organizational outcome.
4. Set explicit boundaries: what is in this opportunity and what is not.
5. Identify uncertainty, counterevidence, dependencies, material risks, and what would change the decision.
6. State the recommended decision and its rationale.
